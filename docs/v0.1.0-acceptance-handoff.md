## Return and decision

Use one report per team, source/client revision pair and deployment/platform profile.
Every applicable case needs status, expected versus observed result, safe reproduction
or command, protected evidence reference/checksum and defect/exception reference.
Return automated pass/fail/skip totals and explicit accepted/rejected/pending sign-off.
Use aliases and access booleans. Exclude passwords, raw callbacks/query strings, tokens,
cookies, record values, identifiers, SQL, unredacted HAR files and key material.
Keep failed-run evidence when rerunning fixes; a behavior fix requires a new candidate.

- [ ] Server team returns endpoint/profile and fresh-invitation readiness through an authorized private channel after separate authorization.
- [ ] App team identifies its last accepted backend ref; any additional spec/vector comparison is supplied.
- [ ] Native and Console teams return applicable cases, both app walks and explicit sign-off.
- [ ] Server team returns actual packaging/isolation/backup/recovery evidence and explicit sign-off.
- [ ] Teams reconcile privacy, grant, revocation and recovery results; no unexplained failure, skip or missing evidence remains.
- [ ] Maintainer records candidate acceptance or named outstanding blockers/approved exceptions.

FAIL, NOT RUN, unexplained skip or absent evidence blocks acceptance. N/A needs a reason
and maintainer agreement; an unavailable shipped feature is not N/A. Historical overlap
cannot be proven by one HTTP run; SV04 must explicitly record that evidence boundary.
Backend gates do not supply independent acceptance. No response or elapsed deadline is
approval. Even completed acceptance does not authorize a tag, publication or deployment;
those remain separate actions, and the App Review freeze remains in force.
