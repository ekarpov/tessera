## Changes since rc.4

- Record-protocol version selection is explicit: highest shared numeric major,
  independent of array order; refuse before authentication/data requests when
  no version is shared. Implementation and content versions are independent.
- A successor record-protocol major must coexist with the previous one for at
  least 12 calendar months after its first production release, extended while
  released clients need the old version. Retirement needs dated operator evidence,
  consumer confirmation, at least 14 days' notice and a discovery announcement.
- Optional discovery `deprecated_versions` entries carry `version` and UTC
  `sunset`. The reusable server and standalone configuration validate entries.
  Invalid configuration fails before storage opens. Dates never disable routes.
  Default discovery is unchanged: v1 is served and no retirement is announced.
- Importable conformance checks now accept additive discovery response fields,
  validate version/deprecation metadata and negotiate before exercising `/v1/`.
  Portable selection and discovery vectors are new files; retained vectors are
  unchanged. Consumers must run the new vectors, not only their previous lists.
- Release/operator rules now require isolated test-server qualification, release
  notes with spec/vector diffs, 2-3 fresh test invitations, app vector/live tests
  and both home/study walks, explicit app confirmation and 14 days' upgrade notice.
- Repository/publication documentation has been reorganized and private references
  cleaned since rc.4. A final-tree and public-ref privacy scan remains required.

## S08 recovery fix in this candidate

Source after the c46beb0 qualification fixes stale identity grants after restoring an
older backup with newer erasure evidence. Startup removes references to absent datasets,
revokes their installations and disables affected fixed-policy issuers before serving.
It preserves unaffected data/account rights and never grants an unowned replacement.
Failed inventory/persistence prevents startup. This repairs existing restored directories
on next startup and needs no schema migration. Old invitations from a disabled issuer
cannot be redeemed; provision a new reviewed policy rather than retargeting the old one.

SQLite and PostgreSQL restore/OAuth regression coverage includes an unaffected dataset,
revoked archived credentials, replacement isolation and repeated restart. The CI endpoints now run 928c09a after a clean committed-candidate gate and installed-
binary recovery regression. Existing CI fixtures/invitations were retained and verified
through isolated pre-upgrade backup restores. The consumer app reports independent compatibility, live integration and server-side
restore checks. Its overall sign-off remains pending; on 8 November the maintainer
waived the remaining iOS app/device tests for the first v0.1.0. Frozen demos remain untouched.

## Behavior and storage review

Record operations, authentication methods, consent/scope ceilings, record-request
validation, capabilities, limits and defaults remain unchanged. Finding 47 adds discovery
metadata validation and explicit version negotiation. S08 additionally fixes restore-time
identity reconciliation and the stale-dataset OAuth approval failure described above;
affected installations and fixed-policy issuers are refused instead of retaining stale
permissions. Configuration gains optional `deprecated_versions`; leave it unset for
this release. No storage migration is added by these changes.

Final `v0.1.0` starts with fresh storage. Pre-release databases, identity registries and
content directories are unsupported inputs. Do not reset review servers to prepare it.
Future released-state migrations remain forward-only; rollback requires compatible
backups and independent retirement evidence rather than an older binary on newer state.

Online filesystem backup acquisition requires local hard-link/flock semantics and at
most 256 required content files. Independent PostgreSQL registry owners cannot capture
coherent archives together. Recovered producer identity does not authenticate arbitrary
artifacts. Real cloud and separate-host recovery are unaccepted; no complete privacy
audit has been performed. Retain keys, trusted producer identity and current retirement
evidence independently. See [backup limits](backup-acquisition.md#content-and-deployment-limits).

## Qualification and acceptance

The final-gate browser helpers avoid eval-based polling that WebKit can reject
under the existing strict CSP. Image completion/dimensions and actual CSP-violation
assertions remain enforced. Browser fixtures also set immutable issuer configuration
before starting HTTP goroutines, removing a fixture startup race exposed by external
browser traffic. No production code, server policy or runtime behavior was changed.

The reference native profile additionally passed concurrent scheduled/manual
acquisition with foreground record writes, content reads and chunk uploads, authenticated
artifact checks, successful/evidence-only/failed publication timestamp rules and journal
repair after restart. Fresh-target recovery with independently retained host keys
preserved committed records and exact content and required fresh transient capabilities.
The run used a dedicated unprivileged UID on real disposable LUKS2 encrypted local ext4,
with the unlock key only in nonswapped RAM. It does not certify the existing unencrypted
synthetic CI deployment or an operator's production storage/custody.

This release claims the Go packages and standalone reference-server profile. An external
Console's deployment kit, credentials, session storage and recovery remain separately
owned and are not included in a Tessera archive or claimed recovered by this package.
Operators retain configuration, TLS/backup keys, trusted producer identity and current
retirement evidence independently. See the
[operator qualification](v0.1.0-s08-acceptance-handoff.md#reference-server-operator-qualification-8-november-2026)
for exact scope and exclusions.

The four previously skipped server-owned WebKit suites now pass with zero skips on
clean preparation commit `94af2f7`, using Playwright 1.58.0 and `go test -race`.
Authorization completion, branding, first-party Console and native consent behavior
were exercised in synthetic desktop/narrow and light/dark variants. This does not
assert acceptance of an external Console application's persistence or UI integration.

The installed Console's existing source tests and four live ordinary-OAuth desktop/
narrow browser flows also passed. The opt-in QR-image export test was skipped.
That client has no first-party remember/session handoff or durable 30-day mode;
its complete W01-W05 integration remains unqualified. The maintainer subsequently
waived the remaining first-party Console-client tests for this v0.1.0 release;
missing client features are not implemented or advertised as passing.

The maintainer explicitly waived the remaining iOS app UI, Home/Study walk,
physical-phone and password-manager acceptance for the first v0.1.0 on 8 November 2026.
These cases are waived/unrun, not passed; the consumer's independent sign-off remains
pending. See the [scoped waiver](v0.1.0-s08-acceptance-handoff.md#maintainer-app-test-waiver-8-november-2026).
Reported selection/discovery vectors passed 17/17 and 21/21; live record/content
integration passed 11 with no failures and one erasure skip. AR02/AR03 and the
server-side AR01 portion passed per the interim return. The
[first-party Console-client waiver](v0.1.0-s08-acceptance-handoff.md#maintainer-first-party-console-waiver-8-november-2026)
is separate from the iOS waiver. Server-owned tests and server/operator qualification
are not waived, and no production encryption, full privacy audit or
unsupported recovery/deployment topology is claimed.
